# עדכון אירועים קרובים

מה שמופיע בקרוסלה "אירועים קרובים" בדף הבית נשמר ב-`src/data/events.json`.
את העדכון מריץ Claude לפי בקשה ("תריץ את סקריפט האירועים"). ההחלטה מה נחשב
אירוע דורשת קריאה של הפוסט, ולכן החלק הזה לא אוטומטי לגמרי.

## המקורות

- **אינסטגרם של כל קיר טיפוס:** 7 הפוסטים האחרונים בכל חשבון, רק מ-30 הימים
  האחרונים (פוסט ישן יותר כמעט תמיד מדבר על אירוע שכבר עבר). הרשימה נלקחת
  מנתוני הקירות באתר (`npm run events:sources`), אז קיר שנוסף לאתר נכנס
  אוטומטית.
- **פייסבוק של כל קיר טיפוס:** אותו דבר, 7 הפוסטים האחרונים מ-30 הימים
  האחרונים בכל דף. הרבה קירות מפרסמים את אותו דבר בשתי הרשתות, אבל חלק
  מפרסמים אירועים רק באחת מהן.
- **התאחדות הטיפוס:** עמוד התחרויות הלאומיות (הכתובת ב-`sources.ts`).
- **מהקהילה:** הקישור "יש לכם אירוע? ספרו לנו" ליד הקרוסלה פותח מייל עם
  תבנית. אירוע שמגיע כך עובר את אותה בדיקה, ואם יש לו קישור הוא נכנס דרך
  `events:merge` כמו כל מועמד אחר.

## מה נחשב אירוע

נכנס רק מה שקורה **פעם אחת, בתאריך ידוע**:

- תחרות, ליגה, פסטיבל, יום הולדת לקיר, ערב מיוחד (`competition` / `special`)
- יום מבצע או הנחה חד-פעמי, למשל לכבוד חג (`sale`)
- סדנה, מפגש או יציאה לטבע חד-פעמיים (`workshop` / `meetup` / `outdoor`)

לא נכנס: חוגים ושיעורים קבועים, הנחה קבועה לפי יום בשבוע, מבצעי מנויים בלי
תאריך, עדכוני בנייה של מסלולים, פרסומות כלליות, ופוסטים על אירוע שכבר עבר.

## שלבים (ל-Claude)

1. `npm run events:sources` - רשימת החשבונות ועמוד ההתאחדות.
2. **התאחדות הטיפוס:** לפתוח בדפדפן את עמוד הליגה הארצית, ומשם את הקישור
   "רשימת תחרויות" (PDF ב-Google Drive, קוראים אותו בצילומי מסך). כל שורה
   עתידית שלא מחוקה בקו היא מועמדת מסוג `competition`, עם `url` לעמוד הליגה,
   `linkLabel: "לפרטים ולהרשמה"` ו-`source: "התאחדות הטיפוס"`. מכניסים את כל
   העונה: תחרות מופיעה באתר רק 30 יום לפניה (ראו "מתי אירוע מופיע"). תחרות
   על כמה ימים רצופים באותו קיר היא אירוע אחד עם `endDate`. תחרות שכבר נכנסה
   מהאינסטגרם של הקיר לא מוסיפים שוב. אם האתר לא זמין, לציין את זה
   בסיכום ולהמשיך.
3. **אינסטגרם:** לכל חשבון לפתוח `https://www.instagram.com/<account>/` בדפדפן
   המובנה, ולהריץ בעמוד את `scripts/events/instagram-latest.js`. הסקריפט מחזיר
   עד 7 פוסטים אחרונים מ-30 הימים האחרונים: קישור, תאריך פרסום וכיתוב מלא.
   חשבון שלא פרסם כלום בחודש האחרון מחזיר רשימה ריקה. אין צורך להתחבר.
4. **פייסבוק:** לכל דף (`facebook` ברשימה) לפתוח את הכתובת בדפדפן המובנה,
   ולהריץ בעמוד את `scripts/events/facebook-latest.js`. הוא מחזיר את אותו מבנה
   כמו סקריפט האינסטגרם. **צריך להיות מחובר לפייסבוק** בדפדפן המובנה (בלי
   התחברות רואים רק את הפוסט האחרון); ההתחברות נשמרת בין הרצות, ואם היא
   פגה - לבקש מהמשתמש להתחבר שוב. ההרצה לוקחת כ-20-30 שניות לדף, אז כדאי
   להריץ כמה דפים ברצף בקריאה אחת. פוסט שכבר נכנס מהאינסטגרם לא מוסיפים שוב.
5. לקרוא כל כיתוב ולהחליט לפי "מה נחשב אירוע". את התאריך לוקחים מהכיתוב
   (למשל "יום חמישי 19.11"), ואת השנה מתאריך הפרסום. אירוע בלי תאריך ברור
   לא נכנס.
6. לכתוב את המועמדים לקובץ JSON זמני: מערך של אירועים עם `title`, `date`,
   `endDate` אם יש, `time` אם יש, `place` (שם הקיר והעיר), `kind`,
   `description` במילים שלנו בשורה-שתיים, `url` של הפוסט, ו-`source`
   (למשל `"Instagram · מאנקיז אשדוד"` או `"Facebook · גקו"`). תחרות של ההתאחדות שנמצאה בפוסט של
   קיר (ליגה ארצית, סימולציית ליגת העל) מקבלת גם `association: true`, כדי
   שתופיע בסינון "התאחדות".
7. `npm run events:merge -- <הקובץ>` - בודק כל מועמד, מעדכן ולא משכפל אירוע
   שכבר קיים (לפי קישור, תאריך ומקום), ומוחק אירועים שפג תוקפם.
8. `npm run build`, ולסכם למשתמש: מה נוסף (עם קישורים), מה נדחה ולמה, ואילו
   מקורות לא היו זמינים. לא לעשות commit בלי בקשה.

## מתי אירוע מופיע ומתי הוא יורד

- **מופיע** 30 יום לפני התאריך שלו (`SHOW_BEFORE_DAYS`). עד אז הוא שמור בקובץ
  ונמצא בדף, אבל מוסתר.
- **יורד** יום אחרי שהסתיים: מוצג עד סוף היום של התאריך שלו, או של `endDate`
  אם יש, ונעלם למחרת (`EXPIRE_AFTER_DAYS = 0`).
  `events:merge` מוחק אותו מהקובץ, וה-build לא מכניס אותו לדף.
- הדפדפן של המבקר בודק את שני התאריכים בכל טעינה, אז אירוע מופיע ויורד בזמן
  גם אם האתר לא עודכן מאז.
- `noExpiry: true` - אירוע שלא יורד לעולם, עד שמוחקים אותו מהקובץ ידנית (כרגע
  רק הודעת "טיפוס ישראל עלה לאוויר!").
