# עדכון אירועים קרובים

מה שמופיע בקרוסלה "אירועים קרובים" בדף הבית נשמר ב-`src/data/events.json`.
את העדכון מריץ Claude לפי בקשה ("תריץ את סקריפט האירועים"). ההחלטה מה נחשב
אירוע דורשת קריאה של הפוסט, ולכן החלק הזה לא אוטומטי לגמרי.

## המקורות

- **אינסטגרם של כל קיר טיפוס:** 7 הפוסטים האחרונים בכל חשבון, רק מ-30 הימים
  האחרונים (פוסט ישן יותר כמעט תמיד מדבר על אירוע שכבר עבר). הרשימה נלקחת
  מנתוני הקירות באתר (`npm run events:sources`), אז קיר שנוסף לאתר נכנס
  אוטומטית.
- **התאחדות הטיפוס:** עמוד התחרויות הלאומיות (הכתובת ב-`sources.ts`).
- **מהקהילה:** הקישור "יש לכם אירוע? ספרו לנו" ליד הקרוסלה פותח מייל עם
  תבנית. אירוע שמגיע כך עובר את אותה בדיקה, ואם יש לו קישור הוא נכנס דרך
  `events:merge` כמו כל מועמד אחר.

## מה נחשב אירוע

נכנס רק מה שקורה **פעם אחת, בתאריך ידוע**:

- תחרות, ליגה, פסטיבל, יום הולדת לקיר, ערב מיוחד (`competition` / `special`)
- יום מבצע או הנחה חד-פעמי, למשל לכבוד חג (`sale`)
- סדנה, מפגש או יציאה לטבע חד-פעמיים (`workshop` / `meetup` / `outdoor`)

לא נכנס: חוגים ושיעורים קבועים, הנחה קבועה לפי יום בשבוע, מבצעי מנויים בלי
תאריך, עדכוני בנייה של מסלולים, פרסומות כלליות, ופוסטים על אירוע שכבר עבר.

## שלבים (ל-Claude)

1. `npm run events:sources` - רשימת החשבונות ועמוד ההתאחדות.
2. **התאחדות הטיפוס:** לפתוח את העמוד בדפדפן. תחרות עם תאריך עתידי היא
   מועמדת מסוג `competition`, עם `url` לעמוד ו-`source: "התאחדות הטיפוס"`.
   אם האתר לא זמין, לציין את זה בסיכום ולהמשיך.
3. **אינסטגרם:** לכל חשבון לפתוח `https://www.instagram.com/<account>/` בדפדפן
   המובנה, ולהריץ בעמוד את `scripts/events/instagram-latest.js`. הסקריפט מחזיר
   עד 7 פוסטים אחרונים מ-30 הימים האחרונים: קישור, תאריך פרסום וכיתוב מלא.
   חשבון שלא פרסם כלום בחודש האחרון מחזיר רשימה ריקה. אין צורך להתחבר.
4. לקרוא כל כיתוב ולהחליט לפי "מה נחשב אירוע". את התאריך לוקחים מהכיתוב
   (למשל "יום חמישי 19.11"), ואת השנה מתאריך הפרסום. אירוע בלי תאריך ברור
   לא נכנס.
5. לכתוב את המועמדים לקובץ JSON זמני: מערך של אירועים עם `title`, `date`,
   `endDate` אם יש, `time` אם יש, `place` (שם הקיר והעיר), `kind`,
   `description` במילים שלנו בשורה-שתיים, `url` של הפוסט, ו-`source`
   (למשל `"Instagram · מאנקיז אשדוד"`).
6. `npm run events:merge -- <הקובץ>` - בודק כל מועמד, מעדכן ולא משכפל אירוע
   שכבר קיים (לפי קישור ותאריך), ומוחק אירועים שפג תוקפם.
7. `npm run build`, ולסכם למשתמש: מה נוסף (עם קישורים), מה נדחה ולמה, ואילו
   מקורות לא היו זמינים. לא לעשות commit בלי בקשה.

## תפוגה

כל אירוע מוצג עד יומיים אחרי התאריך שלו (או אחרי `endDate`), ואז נעלם. זה
קורה בשלושה מקומות: `events:merge` מוחק אותו מהקובץ, ה-build לא מציג אותו,
והדפדפן של המבקר מסיר אותו כשהדף נטען, גם אם האתר לא עודכן מאז.
